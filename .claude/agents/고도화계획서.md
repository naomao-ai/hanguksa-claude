# 한국사능력검정시험 2주 단기 합격 앱 고도화 계획서

본 계획서는 10명의 가상 학생 페르소나 분석 결과와 사용자(프로젝트 오너)의 최종 의사결정을 반영하여, 앱(hanguksa-claude)의 단기 학습 효율을 극대화하기 위한 기능 고도화 방향을 정의합니다. **(코드 수정 없이 문서화된 최종 기획안입니다.)**

---

## 1. 핵심 개선 방향 및 의사결정 반영 사항

### 1.1. UX/UI 포커스: 태블릿(Tablet) 메인 & 반응형 모바일
* **방향:** 책상이나 독서대에서 태블릿을 거치하고 넓은 화면으로 사료와 문제를 분석하는 환경을 '메인 뷰(Main View)'로 설정합니다. 
* **모바일 대응:** 모바일 환경에서도 화면이 깨지거나 답답하지 않도록 Grid/Flexbox 기반의 능동적 반응형 레이아웃(Responsive Layout)을 적용합니다. 
* **구현 포인트:** 
  * 태블릿에서는 [사료/문제]와 [해설/오답노트]를 좌우 분할 화면(Split View)으로 제공하여 스크롤 피로도를 줄임.
  * 모바일에서는 상하 스크롤 및 스와이프 제스처를 통해 부드럽게 화면이 전환되도록 UI 컴포넌트 재설계.

### 1.2. 로그인 및 클라우드 DB 연동 (학습 데이터 동기화)
* **방향:** 기존 로컬 스토리지(localStorage) 의존도를 낮추고, 백엔드 DB 및 로그인 기능을 구축합니다.
* **효과:** 사용자가 스마트폰, 태블릿, PC 등 기기를 변경하더라도 학습 기록(스트릭, 오답노트, 수집 내역 등)이 완벽히 유지되어 끊김 없는 학습 환경을 제공합니다.
* **구현 포인트:**
  * **인증(Auth):** Firebase Auth(소셜 로그인: 구글, 카카오 등) 또는 NextAuth.js 도입.
  * **DB 구축:** 현재 Prisma + SQLite 구조를 유지하되, 클라우드 환경(예: PostgreSQL/Supabase, Vercel Postgres)으로 마이그레이션하거나, 기존 Firebase 인프라(Firestore)를 적극 활용하여 사용자별 데이터 테이블(`User`, `LearningRecord`, `Collection`) 신설.

### 1.3. '수집(Scrap)' 및 노트(Note) 기능 (되새김 학습)
* **방향:** 복잡한 텍스트 하이라이팅 대신, 중요한 사료나 헷갈리는 선지를 **'수집'**하고 **'메모(노트)'**를 남길 수 있는 기능을 도입합니다.
* **효과:** 사용자가 능동적으로 자신만의 '요약 노트'를 만들고, 2주라는 짧은 기간 동안 취약점만 빠르게 되새김(Review)할 수 있습니다.
* **구현 포인트:**
  * 문제 풀이 또는 사료 트레이닝 화면에 **[🔖 수집하기]** 버튼 추가.
  * 수집 시 하단에서 바텀시트(Bottom Sheet)가 올라오며 사용자가 직접 텍스트 노트를 작성 가능.
  * 마이페이지 내 **[나만의 수집 노트]** 탭을 신설하여, 수집된 사료와 메모를 태그/시대별로 모아보기 지원.

### 1.4. 태그 기반 유사 문제 추천 (비용 최적화 및 반복 학습)
* **방향:** 틀린 문제를 복습할 때, AI API를 매번 호출하여 변형 문제를 생성하는 대신 **'기존 문제은행 DB'에서 동일/유사 태그를 가진 문제를 찾아 즉시 제공**합니다.
* **효과:** 불필요한 AI API(Claude) 호출 비용을 방지하면서도, 취약한 유형을 반복 숙달하는 데 필요한 충분한 문항을 제공합니다.
* **구현 포인트:**
  * 각 기출문제의 메타데이터(시대, 인물, 사건, 유형 태그) 매칭 알고리즘 강화.
  * 오답 확인 시 하단에 **"이 문제와 비슷한 유형 다시 풀기 (N문제)"** 버튼 노출.

## 2. 주요 페이지별 고도화 상세 명세

### A. 메인 대시보드 (D-14 벼락치기 모드)
* **학습 현황판:** 로그인 시 사용자 정보를 바탕으로 남은 D-Day, 현재 나의 합격 예측률, 연속 학습일(스트릭) 표시.
* **우선순위 추천:** 클라우드 DB에 저장된 나의 오답 패턴을 분석하여 "오늘 꼭 복습해야 할 태그 Top 3" 제안.

### B. 문제 풀이 및 모의고사 화면 (Tablet First)
* 태블릿 환경에서는 OMR 카드와 문제지가 한 화면에 직관적으로 보이도록 UI 배치.
* 문제별로 [🔖 수집] 아이콘을 상시 노출하여, 풀이 중에도 즉각적인 노트 작성 가능.

### C. 오답노트 및 나만의 수집 노트
* **오답노트:** 틀린 문제 + 정답 해설 + **[유사 문제 풀기]** 트리거 제공.
* **나만의 수집 노트:** 수집한 사료/문항과 내가 작성한 코멘트를 카드형 UI(모바일) 또는 그리드/리스트 UI(태블릿)로 제공.

## 3. 개발 및 마이그레이션 단계 (Action Plan)

| 단계 | 작업 목표 | 주요 세부 내용 |
| :---: | :--- | :--- |
| **Phase 1** | **인프라 및 DB 개편** | - 백엔드 클라우드 DB(PostgreSQL 등) 전환 또는 Firestore 세팅<br>- 소셜 로그인 연동(NextAuth 또는 Firebase Auth)<br>- User, Scrap, Note 스키마 설계 및 Prisma 마이그레이션 |
| **Phase 2** | **반응형 UI/UX 리팩토링** | - 태블릿 중심의 2단 분할 레이아웃 설계<br>- 모바일 스크롤/스와이프 최적화 (Tailwind Breakpoint 활용) |
| **Phase 3** | **수집/노트 & 태그 추천 기능** | - 문제/사료 뷰에 '수집(Scrap)' 버튼 및 메모 팝업(바텀시트) 추가<br>- '나만의 수집 노트' 뷰어 페이지 개발<br>- 태그 기반 유사 문제 쿼리 로직 구현 |
| **Phase 4** | **데이터 연동 및 안정화** | - 기존 로컬 스토리지 데이터를 로그인 시 클라우드 DB로 병합(Sync)하는 로직 구현<br>- 기기 간 동기화 테스트 및 성능(캐싱) 최적화 |

> 위 계획서에 따라 프론트엔드 UI(반응형, 수집 노트)부터 백엔드 DB 연동까지 단계별로 개발을 진행할 수 있습니다.
