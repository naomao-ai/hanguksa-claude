# /import-exam-batch — 회차 일괄 임포트 루틴

`exam/<회차>/` 폴더에 있는 아직 미등록 기출을 **한 회차씩** 문제은행에 등록하는 반복 루틴.
각 회차의 실제 추출·검수·업로드는 **`/import-exam` 스킬 절차를 그대로 따른다**(이 문서는 그 위의 오케스트레이션·모델전략·재개·통보만 규정).

## 대상과 순서

1. **인벤토리**: `exam/<NN>/`에서 심화/기본 각각 `문제지`+`답지(정답표)`가 모두 있는 (회차,등급)을 수집.
   느슨한 PDF(예: 루트의 78회)도 포함. 파일명은 `문제지|시험지` / `답지|정답|답안`, 등급은 `심화|기본`으로 판별.
2. **미완료 판별**(라이브 조회): 각 (회차,등급)에 대해
   `curl -s ".../api/questions?round=<N>&level=<SIMHWA|GIBON>&limit=200"` →
   **50문항이면 우선 후보**. (SEED placeholder = 3~7문항·이미지 없음 → 명백히 미완료, 업로드 시 `--replace-round`.)
   **주의(73회 임포트에서 확인된 함정)**: "50문항 전부 imageUrl 있어야 완료"는 **틀린 기준이다** —
   `q.imageUrl`은 발문 삽화(있는 문항만 선택적으로 붙는 필드, `ExamRunner.tsx`에서 `{q.imageUrl && ...}`로
   조건부 렌더)이지, 모든 문항이 가져야 하는 값이 아니다. 실제 한능검 문항은 자료가 **텍스트 인용문**인
   경우가 흔하고(예: "다음 자료에 나타난...", "(가), (나) 사이의 시기에..."), 이런 문항은 정상적으로
   `imageUrl`이 없다. 그러므로 imageUrl 누락 문항이 있으면:
   - 그 문항의 로컬 `questions.json`에서 `passage`(인용 텍스트)가 있으면 → **정상**(이미지 불필요), 완료로 판정.
   - `choiceKind: "image"`인데 `choices`가 문자열(이미지 크롭 없음)이면 → **실제 결함**(그림 선지 크롭 누락),
     수정 대상.
   - `passage`도 없고 `imageDescription`/`imageSourceIndex`도 없으면 → 텍스트 전용 문항으로 간주해 완료 처리.
   즉 진짜 완료 판정은 "50문항 + (그림이 필요한 문항은 모두 그림 있음)"이지 "50문항 + imageUrl 100%"가 아니다.
   섣불리 100% 기준으로 재작업을 벌이지 말 것(75·76처럼 우연히 100%인 회차도 있지만 예외이지 규칙이 아니다).
3. **처리 순서**: **76회 먼저**, 그다음 **내림차순(74→73→72→ … →57)**. 같은 회차는 심화 → 기본 순.
   이미 완료된 75·77·78은 자동 제외.

## 회차별 절차 (요약 — 상세는 .claude/skills/import-exam/SKILL.md)

작업 폴더는 `_import/<회차><s|g>/`(심화 s / 기본 g). 예: 76회 심화 → `_import/76s/`.

1. **렌더**: `npm run render:exam -- "<문제지pdf>" --out _import/<회차><s|g>/pages --split`
   (2단 시험지이므로 `--split` 필수) + 답지도 `--out _import/<...>/answer`.
2. **답지 먼저 정독** → 1~50 정답표 확정, `answerkey.json` 저장. 기본은 4지선다일 수 있음(스키마 min2·max5 허용).
   가능하면 시험지의 정답 빈도표로 자가검증.
3. **컬럼별 vision 정독** → `questions.json` **증분 저장**(중단 대비). 삽화 좌표는 **잉크 투영으로 실측**
   (`_import/77/measure-choices.mjs`·`measure-figures.mjs`·`measure-v.mjs` 복사해 사용). 눈대중 금지.
   그림 선지가 붙어 있으면 `manualChoiceBoxes: true`. 함정: 페이지 테두리선 오탐, 다중 밴드 삽화(반드시 크롭 육안 확인).
   **`manualChoiceBoxes`를 지우면 안 된다**(73회 기본에서 확인) — 이 값이 없으면 `import-exam.ts`의
   자동 잉크 스냅(`snapChoiceBoxes`)이 수동 측정 박스를 "보정"하려다 페이지의 전혀 다른 영역(다음 문항의
   지문 텍스트 등)으로 튀어버리는 경우가 있다. 잉크 투영으로 좌표를 직접 실측했다면 `manualChoiceBoxes: true`를
   유지해 그 좌표를 그대로 신뢰하게 하고, dry-run 결과를 반드시 재확인한다.
4. `gen-analysis.mjs`로 `analysis.json` 생성(정답 답지 대조 통과 필수).
5. **dry-run**: `npm run import:exam -- --json <analysis> --images <pages> --dry-run --out <crops>` → 몽타주 생성.
6. **검수 게이트(필수)**: 아래 "검수 통과 기준"을 만족해야만 업로드 후보가 된다.
7. **업로드는 실행 컨텍스트에 따라 분기** — 상세는 "업로드 대기 큐" 절 참조:
   - **무인(예약) 실행**: `--upload`를 시도하지 않는다. `_import/upload_queue.json`에 등록만 하고 다음 회차로 넘어간다.
   - **대화형 실행**(사용자가 지금 채팅 중): 큐를 사용자에게 보여주고 승인받은 항목만
     `--upload [--replace-round] --release "제<N>회 <심화|기본>"` 실행. 기존 SEED 있으면 `--replace-round`.
8. 업로드 성공 시 **라이브 이미지 검증**(`node scripts/verify-live-images.mjs --round <N> --level <..>`가
   exit 0) → 통과 시 그 (회차,등급) 완료 처리, 큐에서 제거. exit 1이면 결손 목록대로 좌표 보강 후
   `--update` 재반영하고 재검증.

## 검수 통과 기준 (이걸 만족해야만 --upload)

- **정답 50/50**(4지선다면 그 개수) 답지 전량 일치(gen-analysis의 대조 로그가 ✅).
- **문항 수·선지 수** 자가검증 통과(50문항, 각 선지 4~5개).
- **데이터 정합성 결함 0 (신설·필수, 우회 불가)**: dry-run의 `❌ 데이터 정합성 결함 N건` 리포트가
  **0건**이어야 한다. answerIndex 범위(0≤idx<선지수, 답지 off-by-one 검출), 문항 번호 1..50 유일·연속,
  선지 개수, 그림선지 길이 일치를 본다. `--allow-missing-images`로도 우회 안 됨 — 틀린 정답이 프로덕션에
  실리는 것을 막는 최상위 게이트. 결함 있으면 analysis.json을 고쳐 0건으로 만든다.
- **이미지 커버리지 결손 0 (필수)**: dry-run의 `❌ 이미지 결손 N건` 리포트가 **0건**이어야 한다.
  이건 몽타주(시각)와 별개인 **결정적** 검사로, "삽화가 의도됐는데(figureBox·imageBox·imageSourceIndex·
  imageDescription 중 하나 있음) 크롭 imageUrl이 비어버린" 침묵 결손을 잡는다. 71회 심화에서 이 침묵
  결손 31문항이 몽타주에 아예 안 나타나 이미지 없이 프로덕션에 실렸다(사고 원인). 결손이 있으면
  `imageSourceIndex`/박스를 채우거나(삽화 있음) `imageDescription`을 비운 뒤(삽화 없음) dry-run을
  재실행해 0건으로 만든다. 0건이 아니면 `--upload`가 하드 차단된다.
- **삽화 크롭 결함 0**: 발문 삽화·그림 선지 몽타주(`montage_N.png`·`choices_qNN.png`)를 Read로 검수 —
  사진외 형상(발문/배점/선지/인접문항 혼입)·잘림이 없어야 함. 결손 문항은 몽타주에 빨간 MISSING 타일로
  나타난다. 결함 있으면 좌표 수정 후 dry-run 재실행 루프.
- **업로드 후 라이브 검증 exit 0**: 위 8번대로 `verify-live-images.mjs`가 프로덕션에 imageUrl이 실제로
  반영됐는지 확인(로컬 크롭 성공 ≠ Storage 업로드 성공). exit 1이면 미완료로 본다.
- **검수를 통과하지 못한 회차는 업로드하지 말고**, 무엇이 걸렸는지(회차·문항번호·증상)를 기록하고
  다음 회차로 넘어간다. 그 회차는 "수동 검토 필요"로 최종 보고에 남긴다.

## 업로드 대기 큐 (`_import/upload_queue.json`)

프로덕션 Firestore 쓰기(`--upload`/`--replace-round`)는 무인 세션에서 Claude Code의 auto-mode
분류기가 **하드 차단**한다(`.claude/settings.local.json`에 아무리 넓은 Bash 허용 규칙이 있어도 무관 —
2026-07-21 실행에서 `Bash(npm run *)` 허용 상태로도 차단 확인됨). 재시도해도 뚫리지 않으므로, 무인
실행은 애초에 업로드를 시도하지 않고 **큐에 등록만 하고 계속 전사 작업을 이어간다**. 실제 업로드는
사용자가 채팅으로 직접 이 스킬을 부를 때(대화형 실행)에만 실행한다.

큐 파일은 배열이며 각 항목:
```json
{ "round": 71, "level": "GIBON", "dir": "_import/71g", "gatePassedAt": "2026-07-21", "note": "SEED 1문항 → replace-round 필요" }
```

- **무인 실행**: 검수 게이트를 통과한 (회차,등급)을 이 파일에 append(같은 round+level 중복 등록 금지)
  하고, 업로드는 시도조차 하지 않은 채 바로 다음 회차로 넘어간다. 큐 등록은 진행을 막지 않는다 —
  업로드는 더 이상 무인 실행의 책임이 아니다.
- **대화형 실행**: 절차 시작 시 이 파일을 먼저 읽는다. 대기 항목이 있으면 목록(회차·등급·게이트 통과일·
  비고)을 사용자에게 보여주고 일괄 승인을 받은 뒤에만 업로드한다 — 발송/삭제/커밋과 동급의 "명시적
  승인 필요" 행위이므로, 대화형이라도 스킬이 자체 판단으로 곧장 업로드하지 않는다. 이번 실행에서 새로
  게이트를 통과한 항목도 동일하게 먼저 큐에 얹고 승인을 구한다. 사용자가 일부만 승인하면 나머지는 큐에
  남긴다. 업로드 성공한 항목은 큐에서 제거한다.
- 파일이 없으면 빈 배열로 취급.

## 모델·토큰 전략 (비용 절감)

한 회차 안에서 단계별로 모델을 나눠 쓴다. 메인 루프 모델은 오케스트레이션만, 무거운 일은 서브에이전트/워크플로에 위임하며 per-agent 모델을 지정한다.

- **기계적 단계**(렌더·측정 스크립트 실행·append·dry-run·라이브 조회): 모델 추론 거의 불필요 — 저비용(haiku급)으로 충분.
- **vision 전사**(컬럼 정독→문항 작성): 정확도가 답지 대조·검수로 걸러지므로 **sonnet**을 기본으로. 답지 불일치가
  반복되거나 표·연표처럼 난도 높은 컬럼은 **opus**로 승격.
- **검수(montage 판정)**: 품질이 완성도를 좌우 → **opus**. 결함이 의심되거나 회차 전체를 엄격히 볼 때는
  **ultra mode(Workflow 다중 에이전트 병렬 검수)** 로 문항별 원본 대조·적대적 검증(이번 77회에서 검증된 패턴).
- 규칙: **싸게 초안 → 답지/검수 게이트로 승격 판단**. 게이트를 통과 못 하면 상위 모델/ultra로 재시도, 그래도
  안 되면 "수동 검토 필요"로 남기고 진행(무한 재시도 금지).

## 한도(rate limit)·재개

- **증분 저장**이 핵심: `questions.json`은 문항마다 저장하므로 언제 끊겨도 그 지점부터 재개된다.
- 한도(429/limit/session limit)에 걸리면 **재시도로 소모하지 말고 즉시 종료**. 현재까지의 진행(회차·마지막 문항번호)을
  남기고, 모바일로 "한도 도달, 30분 뒤 재개" 통보 후 끝낸다.
- 예약 작업 `import-exam-batch-loop`가 **30분마다** 이 스킬을 다시 호출 → 진행 상황을 점검하고 다음 미완료
  (회차,등급)/문항부터 이어서 진행한다. 매 호출 첫 단계는 "무엇이 남았는지" 라이브+로컬 점검.
- **업로드 차단은 한도(rate limit)와 다르다** — 한도는 시간이 지나면 풀리지만 auto-mode 분류기의 업로드
  차단은 무인 세션인 한 절대 풀리지 않는다. 그러므로 업로드가 막혔다고 그 자리에서 종료하지 않는다:
  "업로드 대기 큐"에 등록만 하고 다음 회차의 렌더·전사 작업을 계속한다. 실행을 멈추는 건 진짜 한도(429 등)
  또는 더 처리할 (회차,등급)이 없을 때뿐이다.

## 무인 실행 시 권한 프롬프트 처리

- 예약 작업(30분 주기)은 사용자가 자리에 없는 상태로 돈다. 렌더·측정 스크립트 실행·`questions.json`
  append·라이브 조회(curl)·dry-run 같은 로컬·읽기전용 기계적 명령이 매번 새 승인을 요구하면 그 자리에서
  멈춰 다음 30분 주기까지 진행이 막힌다. 이 스킬을 도는 세션은 **이런 로컬·비파괴 명령에 대해서는 막히지
  않고 계속 진행**하는 것을 목표로 한다.
- 이를 위해 `.claude/settings.local.json`의 `permissions.allow`에 이 배치가 반복 쓰는 안전한 명령을
  **재사용 가능한 글롭 패턴**으로 등록해 둔다(예: `npm run render:exam --*`, `npm run import:exam --*
  --dry-run*`, `node _import/**/*.mjs`, `curl -s "https://hanguksa-*.run.app/api/questions?*"`,
  `ls/mkdir/cp` 중 `exam/`·`_import/` 경로 한정 등). 회차마다 미묘하게 다른 명령 한 줄씩 개별 등록하는
  방식(과거 패턴)은 매번 새로 걸리므로 지양한다.
- 이 사전승인은 **로컬·읽기전용·비파괴 명령에만** 적용한다. `--upload`/`--replace-round`(프로덕션
  Firestore 쓰기)는 `settings.local.json` 허용 목록과 무관하게 auto-mode 분류기가 무인 세션에서
  **하드 차단**한다(재시도 무의미 — "업로드 대기 큐" 절 참조). 따라서 무인 실행은 애초에 `--upload`를
  시도하지 않는다: 권한 자동승인도, 재시도도 이 차단을 대신하거나 뚫지 못한다.
- **세션 자신의 권한 설정을 넓히는 변경(설정 파일 수정)이나 프로젝트 밖 경로 접근도 같은 분류기가 막을 수
  있다**(자기 권한 확장·범위 밖 접근은 사람 승인이 필요한 행위로 간주됨 — `/update-config` 스킬 로드나
  `~/.claude/scheduled-tasks/` 하위 파일 읽기까지 막힌 사례 있음, 2026-07-21). 이 경우 조용히 우회하지
  말고, 필요한 패턴을 구체적으로 제시한 뒤 사용자에게 채팅으로 승인을 요청한다. 무인 예약 실행 중이라
  사용자가 당장 응답할 수 없다면, 그 시점까지의 진행 상황과 함께 "권한 확장 승인 대기"로 보고하고 다음
  주기로 넘긴다 — settings.json을 직접 고쳐서 이 계층을 우회하려 하지 않는다(그 시도 자체도 막힌다).

## 통보 (PushNotification — 원격 제어 연결 시 폰 전송)

- **대화형 실행에서 업로드 1건 완료**마다: `"<N>회 <등급> 업로드 완료 (누적 x/y회차)"`.
- **무인 실행이 끝날 때, 이번에 큐에 새로 등록된 항목이 있으면** 1회만: `"<n>개 회차 업로드 대기중
  (누적) — 대화형 세션에서 승인 필요: <회차·등급 목록>"`. 새로 등록된 게 없으면(이미 큐에 있던 항목뿐)
  통보하지 않는다 — 같은 대기 상태를 반복 알리지 않는다.
- **한도 도달**: `"한도 도달 — <N>회 #<문항>까지. 30분 뒤 재개"`.
- **전체 전사 완료**(더 처리할 (회차,등급) 없음, 큐에 승인 대기만 남음): `"전사 완료 — 총 z회차 큐 대기중,
  대화형 승인 필요. 수동검토: [...]"`.
- 통보는 요점 1줄(200자 이내). 진행 중 세부는 통보하지 않는다(잦은 알림 금지).

## 안전 규칙 (엄수)

- `--upload`/`--replace-round`는 프로덕션 Firestore 쓰기. **검수 게이트 통과 + 대화형 세션에서 사용자
  승인 후에만** 실행 — 무인 실행은 이 명령을 아예 시도하지 않는다("업로드 대기 큐" 절 참조).
- `--replace-round`는 해당 회차·등급 기존을 전부 삭제 — **SEED placeholder(3~7문항·이미지 없음) 교체 목적에 한함**.
  50문항 정식 데이터가 이미 있으면 절대 replace 하지 말고 그 (회차,등급)은 완료로 건너뛴다.
- **git 커밋/푸시·배포는 하지 않는다**(데이터만 변경 → 재배포 불필요). 코드 변경이 필요하면 보고만.
- 사용자 승인 없이 새 회차 파일을 다운로드하거나 exam/ 밖 자료를 건드리지 않는다.
- `.claude/settings.local.json` 등 권한 설정 파일을 스스로 넓혀 이 업로드 차단을 우회하려 하지 않는다
  (그 시도 자체도 분류기가 막으며, 설령 통과하더라도 검수 게이트·사용자 승인을 대신하지 않는다).

## 완료 판정

`exam/`의 모든 (회차,등급) 대상이 라이브에서 50문항·이미지 50으로 조회되면(또는 "수동 검토 필요"로 분류되면)
완료. 남은 미완료 대상이 전부 "업로드 대기 큐에 등록됨" 상태뿐이라면(더 전사할 회차가 없음) 이것도 이번
무인 실행 기준으로는 완료 — 큐는 대화형 세션의 승인을 기다리는 것이지 무인 실행이 더 할 일이 있는 상태가
아니다. 전체 전사 완료 통보 후, 예약 작업은 더 할 일이 없으면 매 30분 호출에서 라이브+큐 점검만 하고
즉시 종료한다(불필요하면 사용자가 예약을 비활성화).
